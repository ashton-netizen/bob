## The five biggest active decisions, with rationale
1. Plugin, not a custom local app (20 October 2026). The pains were enforcement failures plus setup failures; a plugin fixes both without a third thing to install, and runs under each person's own Claude seat. The custom app and hand-built adapter are shelved as a measured fallback.
2. Team seats, no API keys (20 October 2026). The Agent SDK docs bar third-party products from offering claude.ai login; a plugin inside the user's own Claude Code sidesteps that. Plan tier to be read from the account at kickoff.
3. Git-tracked files as the store, not a database (20 October 2026). Single user per repo in v1; `bob/schema.json` is the one home for shapes and states.
4. First job is `/bob adopt` on AquaAgent, 10 days (20 October 2026). Proves "make existing builds brilliant" before any greenfield work.
5. Pane spike before any gate code (20 October 2026). It is the one assumption that can send the design back; the fallback is `docs/status.html` written by the same hooks.

## Decisions taken in the Build 2 session (21 October 2026, Part A)
- `bob/schema.json` is read from the plugin folder only, by the hooks module (`$.plugin.root`) and by `scripts/preflight.sh` (its own parent folder). An adopted repo never gets a copy. The preflight requires `docs/project-status.md` only once `bob/brief.json` exists; `/bob adopt` creates it when absent.
- `/bob adopt` reads one proposal file, `docs/evidence/adopt/adopt-proposal.json`, and refuses the whole proposal with every reason listed if any record breaks the schema: base fields, `is_synthetic` must be false, requirement states, `verified` or `accepted` only with an evidence record of a schema kind, source `access` and `processing` values, no approvals, no active increment. It writes `bob/brief.json` LAST so Gate A engages only once every file exists, and it never runs git: the commit is a Gate A decision in the session.
- `/bob approve <id>` is the only writer of `bob/approvals.json`. It appends one immutable record (brief sha256, approver from `git config user.name`, `source: human`), sets the increment approved then active, and refuses a duplicate at the same hash, a second active increment, a closed increment, and a non-human origin (the engine stamps `command.run` with `origin.kind`; plugin, sdk, scheduled and the other machine kinds are refused). Gate A denials now point at `/bob approve <id>` instead of hand-writing JSON.
- The test file's schema copy (`SCHEMA` in hooks/bob.test.tsx) now mirrors the source and evidence value lists from `bob/schema.json`. It is a test double, not a second home: if `bob/schema.json` changes a value list, change the double too or the adopt tests lie.

## Known landmines
- RELATIVE PATHS RESOLVE TO THE PLUGIN FOLDER, NOT THE REPO (seen live 21 October 2026, Part B step 8). `$.fs.read`, `exists`, `write` and `stat` take a path "relative to the working directory", and in a session that working directory is the plugin's own folder: `/bob adopt` on AquaAgent refused "bob/ledger.json already exists" (the plugin ships one) and Gate A's `load()` read the plugin folder too, so a governed repo would never have engaged the gates. Plugin 0.2.1 resolves every repo path under `$.session.root()` and runs the preflight and `git config` with `cwd` set to it. The kit masked it: its path helper matched the tail of any path; it now serves repo files only under a stubbed session root and resolves a bare path elsewhere (hooks/bob.test.tsx `ROOT`, `ELSEWHERE`). Rule from it: a repo path is always `at(root, ...)`; a plugin file is always `${$.plugin.root}/...`; a bare path is a defect.
- AquaAgent main IS protected: by repository ruleset 24340162 "main protection" (pull request required, no bypass actors, six required checks with the strict policy, no force-push, no deletion). `gh api repos/<owner>/<repo>/branches/main/protection` answers 404 for ruleset protection; read `gh api repos/<owner>/<repo>/rulesets` first. The Build 2 preflight line "AquaAgent main is unprotected" is wrong.
- `/bob <command>` is typed by a person at the prompt box. The session's Skill tool refuses it ("a built-in CLI command, not a skill"), so the kickoff's "Claude types /bob adopt" is in practice "Ash needs to type /bob adopt" after Claude has written the proposal. A command typed before the plugin has registered in that session does nothing visible.
- TWO ENGINES ON ASH'S MAC. `claude` on PATH is 2.1.287 (Homebrew); the desktop app runs its own 2.1.304 at `~/Library/Application Support/Claude/claude-code/2.1.304/<hash>/claude.app/Contents/MacOS/claude`. The pane's Text `weight` prop is refused by 2.1.287, so `claude plugin test` from a Terminal fails while the same test passes in the app's engine. Version floor: 2.1.304. Run validate and test with the bundled binary, or update Homebrew's claude.
- `gitleaks/gitleaks-action@v2` needs `permissions: pull-requests: read` on its job or it dies with a 403 before scanning (seen red for the wrong reason on the first run).
- `claude plugin validate .` warns that CLAUDE.md at the plugin root is not loaded as plugin context. Correct: it is repo context for Claude Code sessions on this repo, not something the plugin ships.
- The test kit's `$.ui` has no `invalidate`; the module wraps the call in try/catch. The scan also refuses `typeof $.ui.invalidate`; every `$` use must be a call.
- `atom()` references must be string literals (`{ plugin: 'bob', key: '...' }`), not a const; the scan refuses otherwise.
