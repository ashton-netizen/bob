Why it drifted

Every build measured rules, not people.Each kickoff's done list checked gates and tests. None checked whether Mags could start and steer a project without typing commands, though the plan named that as load-bearing assumption 3.
The design gate never fired.The plan deferred the look to "after a wireframe approval and a mockup approval". Neither was ever drawn, so the default pane became the product.
Choosing a plugin traded away the visual app.That was the right call for reach and safety, but nobody then designed what the workspace looks like inside a pane beside the chat.

What Claude tests before any build

This wireframe assumes three things the engine has not been tested on. Claude proves each one in a throwaway folder first. If one fails, the design changes before any code is written.

Test 1A button in the pane can start a BOB action, like starting a project or approving a round. The engine has a Button component; whether a click can run BOB's own actions has not been tested.
Test 2Saying the idea in plain words starts the project, with Claude choosing the name. Today only a typed command can do this.
Test 3A click in the pane counts as a person for Gate A, so approvals stay out of Claude's reach.

Next step. Ash approves this wireframe or marks what to change. Claude then runs the three tests and writes the next build kickoff around this experience, not around more rules.
